# 卡片网络监测

从 v1.5.0 开始，普通服务器卡片支持最多三条线路的延迟、丢包率和最近一小时历史色条。沿用主题现有颜色、圆角与磨砂设置，行内模式保持原样。

## 设置方法

1. 导入 v1.5.0 或更新版本的主题包。
2. 打开 Komari 后台的主题管理，找到 **卡片网络监测**。
3. 打开 **显示卡片延迟与丢包**。
4. 在 **卡片监测任务** 中填写 JSON 数组。例如：

```json
["联通", "移动+35", "电信"]
```

也可以使用后台 Ping 任务的数字 ID：

```json
[1, 2, 3]
```

填写顺序就是显示顺序，可以选择一至三项。优先按名称精确匹配；只有名称包含匹配结果唯一时才使用包含匹配。重名或同类任务较多时建议使用任务 ID。

任务应先在 Komari 后台创建并关联到相应服务器。主题设置只选择展示内容，不会创建或修改后台任务。

## 为不同服务器指定任务

**服务器监测任务覆盖** 是可选 JSON 对象，支持按 UUID、卡片 ID 或名称覆盖，优先级依次为 UUID、卡片 ID、名称。

```json
{
  "Ciallo-HK": [1, 2, 3],
  "Tokyo": [4, 5, 6]
}
```

未单独配置的服务器继承全局任务。清空覆盖输入框即可全部恢复全局配置。

## 数据含义

- 左侧数值是最新一次采样的延迟，左侧色条表示各时间段的平均有效延迟。
- 右侧数值是最近一小时的真实丢包率，右侧色条表示各时间段的丢包率。聚合数据按实际样本数加权。
- 色条分为 30 格，每格约两分钟。缺少采样时留空，不推算丢包或填充旧延迟。
- 鼠标悬停显示该时间段的延迟和丢包信息；键盘聚焦后可用左右方向键查看。
- 服务器离线时显示“监测已中断”和 `--`，保留截止最后上报时的历史，尾部留空。服务器在线但该任务记录过期时显示“已过期”。
- 全部卡片共享最近一小时的记录，每分钟刷新一次。请求失败时提示“刷新失败”，历史色条仍可查看，但当前数值不会冒充实时读数。
- 支持 Komari Metrics 接口；较旧版本自动回退到 `common:getRecords`。

关闭 **显示卡片延迟与丢包** 可恢复原卡片高度，同时停止首页监测记录请求。
